## 2. 判断の内容

### 2.1 M7-3（Runner Image）【GPT判断。承認は本人判断項目1 として未決定】
- 正式G2 の評価ジョブの Runner Image は、ジョブログの「Set up job → Runner Image」グループの **Image の値**で識別し、`ubuntu-24.04` を基準とする。評価側 baseline の固定条件は Image だけとする。
- **Version は実行ごとの観測値**としてジョブログから記録し、基準との一致は求めない。プロセスの環境変数 ImageOS・ImageVersion は観測値として記録するだけで、照合には使わない。
- 07f §6.7 の「識別値はジョブログの Image・Version」という承認文案は、本項の内容に改める。M7-3 の承認を求めるときは、本項の文案を使う。
- 残余リスク：Version の更新によって、lock の外にあるシステムのソフトウェアが変わり、評価の結果に影響しうる。これは Python の版・lock・installed・code の照合では検出できない範囲として受け入れる。

### 2.2 Version の扱い【GPT判断（2026-11-06 00:53）】
- Version の値が基準や過去の実行と違うことは、不合格の理由にしない。
- 一方、ジョブログに Version の行が無い、または一意に読めない場合は、観測の証跡が欠けているものとして、そのジョブログの検証を不合格にする。
- Image を一意に取り出せない、または Image が基準と違う場合は、その実行を正式カウントに入れない。

### 2.3 評価側と集約側の baseline を分ける【GPT判断】
- **評価側の baseline**：評価に使う42件のファイルの SHA-256、lock、Python の版、installed、設定、motor_history の先頭行、読み込むモジュールの許可一覧、Runner Image の Image。
- **集約側の baseline**：集約の4ファイル（`rebuild/formal_g2/aggregate/main.py`・`__init__.py`・`fetch_log.py`・`.github/workflows/formal_g2_aggregate.yml`）の SHA-256 と、Python の版。
- gh・jq の版は観測値として記録するだけで、照合しない。
- 07f §6.7 は基準を1つとして書いているが、本項で2つに分ける。

### 2.4 §6.8 B の条件5【GPT判断。07g §3.8 の5 を置き換える】
- 新しい条件：**評価ジョブは、リポジトリ取得用の認証情報を作成・使用・保持しない。**
- 確かめる方法（3層）：
  1. 静的な検査：workflow で checkout を使わず、`credential`・`extraheader` を設定せず、トークンを参照しないこと。
  2. 取得のステップの中の検査：匿名で取得したあと、git の認証設定・資格情報のファイル・`GIT_ASKPASS`・名前に TOKEN を含む環境変数が無いことを確かめ、あれば停止すること。
  3. 実行の証跡：ジョブログに取得のステップの出力（`g2_credentials_check=none`・`g2_fetch_head=<SHA>`）があり、アクションの入力に値が `***` のトークンが無いこと。
- 07g §3.8 の旧条件5「評価ジョブの checkout で `persist-credentials: false` を設定する」は、本項で置き換える。

### 2.5 §6.8 B の条件3【GPT判断。07g §3.8 の3 の文言を補う】
- GITHUB_TOKEN を使えるのは集約ジョブだけとする。
- 集約ジョブの権限は、artifact・ジョブログ・実行情報の取得に必要な `actions: read` と、checkout に必要な `contents: read` に限る。用途と必要性を記録し、ほかの権限は加えない。
- 07g §3.8 の3「権限は最低限の actions: read」は、本項の範囲で読む。

### 2.6 条件1・3・6 の適用範囲と、トークンの区別【GPT判断】

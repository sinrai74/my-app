## 3. 判断内容

### 判断1：案C の正式採用 — A

1. 案C の本文仕様（F2）は、既にユーザーが承認済みであり、本判断で改めて変更しない。
2. 案C を、Phase0.5 との次の差分5点を含めて、正式な実装判断として承認する。

| # | Phase0.5 との差分 | Phase0.5 の該当規定 |
|---|---|---|
| ① | メール本文の formatter を `notification/`（`notification/body_formatter.py`）に置くこと | ⑦・⑧、ディレクトリ構成（メール本文は `output/text/mail_bodies.py`） |
| ② | 保存済みでない、実行中の RaceEvaluation・Prediction・BuyDecision を入力に使うこと | ⑦（L4 の入力は保存済みデータのみ） |
| ③ | テンプレートを使わないこと（件名・本文の文言をコードに直接記述することを含む） | ⑦（テンプレート＋brand 設定から生成） |
| ④ | brand 設定（`config/brand.json`）を使わないこと | ⑦・⑮ |
| ⑤ | L4／L5 の責務を、案C の構成（独立 formatter を `actions/production_entrypoint.py` から呼び、NotificationService・MailNotifier は本文を組み立てない）に合わせること | §2.2・⑦・⑧ |

3. 本判断は Phase0.5 設計固定書を書き換えるものではない。上記5点は、Phase0.5 に対する差分として正式に承認したものである。
4. 本判断により、`notification/body_formatter.py` は、上記の差分を承認された正式な実装として、C5 の判定の対象となる。

### 判断2：byte一致テスト — A

1. 案C のメール本文について、Legacy の生成物との byte 一致を、C5 の判定条件としない。
2. 理由：案C は Legacy のメール本文の完全再現を目的としておらず（F2）、byte 一致の比較対象となる Legacy の生成物も定義されていない（F5）。
3. 本判断は、G5 の既存の定義（Step5-0・Step6-0 の G5 [A]、継続基準書 §9 の G5 [B]）、G5 [A]・[B] の関係、G5 の FROZEN の状態、Go/No-Go 条件としての G5 の扱いを変更しない。
4. 本判断は、継続基準書 §8 の記載を書き換えない。

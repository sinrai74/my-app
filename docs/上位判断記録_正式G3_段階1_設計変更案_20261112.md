## 2. 型と純関数

### 2.1 ML 加点の純関数
```
apply_ml_bonus(upset_score: float, target_lanes: tuple[int, ...],
               win_probs: dict[int, float], lane_order: tuple[int, ...])
  -> MlBonusResult(score_post, target_post, applied: bool, bonus: float)
```
- 規則は notify_arashi.py 3463〜3476行目と同じ（D11）。lane_order は boats の並び。
- win_probs が空なら applied=False、score_post=upset_score、target_post=target_lanes。

### 2.2 型を分ける
- **MlBonusResult**（Rebuild 由来）：score_post・target_post・applied・bonus。
- **BuyScoreInput**（Legacy の `_evaluate_bets` の中で写し取った値）：eval_id・pred_combo・uncertainty・disagreement・composite・has_exhibition・market_gap・match_index_approx。
- match_index は持たせず、評価の中で `compute_match_index(score_post)` で導く。
- 範囲：uncertainty・disagreement・composite は 0〜1。market_gap は実数（負を含む）。score_post は 0 以上（9.5 を超えうる）。範囲外・None・型違い・欠けは ValidationError。純関数の既定値の補完（Step4-6）は変えない。

### 2.3 入力つきの評価
- 既存の `DefaultBuyEngine.assess(evaluation, prediction, config)` と BuyPipeline の呼び出しは変えない（D8）。
- 入力つきの評価は、別の入口（A では assess の別メソッド、B では新しいファイルの関数）にする。
- 候補：Prediction の4項目に uncertainty・disagreement・composite を加える。context：match_index=compute_match_index(score_post)、match_index_approx、race_type=evaluation.race_type、has_exhibition、market_gap、upset_score=score_post、ex_rank_1st=0（Legacy の7キーと同じ形。notify_arashi.py 2705〜2713行目）。

## 3. win_probs の注入

- G3 用の組み立てで、Legacy の `_predict_win_prob` を包む predictor を Ver4Engine に注入する（engine.py の注入口を使う。engine.py は変えない）。
- predictor は eval_id しか受け取らないので、eval_id から boats を引く対応表を、組み立ての中で持つ。
- 加点の入力・PredictionContext.ml_probs は、どちらも RaceEvaluation.win_probs から取る（`_predict_win_prob` を二度呼ばない）。
- 失敗時は `{}`。`{}` と None の扱いは §4 の条件8。
- 正式G2 の評価は predictor=None のまま（G2 では `_predict_win_prob` は禁止区分。instrument.py 77行目）。

## 5. 本番の入口・Shadow への影響（再評価）

## 3. 判断内容（L439 承認）

Phase0.5 §⑥ L439（「表にない新ファイルの作成はレビュー必須」）に基づき、次の新規 Release アセットの追加を承認する。

保存先：**Releases / `data-store`**

| アセット名 | 元ファイル |
|---|---|
| `hit_record_legacy44_20260704.csv` | `C:\Users\81809\Desktop\my-app\hit_record.csv` |
| `hit_record_legacy37_20260704.csv` | `C:\Users\81809\Desktop\my-app\hit_record_backup_20260705_202325.csv` |

承認理由：

- 44列版は、⑨-1 が求める44列スキーマの実データである。
- 37列版には、44列版からは復元できない145件の修正前の状態（`purchased`・`skip_reason`）が残っている。
- 34列版は37列版と完全に一致するため、保存しない。
- 22列版は、F-1 で保全済みのデータと SHA-256 が完全に一致するため、保存しない。
- 37列版と44列版の差分は `purchased`・`skip_reason` の145件であり、修正の前後を監査できる状態を保持する価値がある。

アセット名は、Phase0.5 §⑪（L602）の Releases アセットの命名規則 `{name}_{version|date}.{ext}` と、v1.1.8 の「スナップショットの日付はデータの開催日由来（JST）」に従い、F-1 の `hit_record_legacy22_20260703.csv` と同じ形とした。現行運用の `hit_record.csv` と同じ名前では保存していない。

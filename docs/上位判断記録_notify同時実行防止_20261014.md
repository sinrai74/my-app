## 3. 判断（ユーザー判断、2026-10-14）

1. **notify の同時実行を防止する。** 購入ログの記録・履歴が失われることを防ぐための、⑳20.3 の障害修正として扱う。
2. **変更内容**：`.github/workflows/notify_arashi.yml` の `on:` と `jobs:` の間に、次の設定（コメント1行を含む）を追加する。他の行・他のファイル・改行コード（CRLF）は変えない。`notify_arashi.py` は変更しない。

   ```yaml
   # ── 同時実行の防止 ──
   concurrency:
     group: notify-arashi
     cancel-in-progress: false
   ```

3. **`cancel-in-progress: false` とする。** 実行中の回を途中で止めると、保存の②〜③の途中で止まり、本体がない状態が残るおそれがあるため（F1）。
4. **待機中の実行の扱い**：GitHub Actions の仕様（公式ドキュメントの記載。本書の作成時に再確認はしていない）では、同じ group で待機中の実行があるときに新しい実行が来ると、待機中の古い実行は取り消される（同時に「実行中1つ＋待機中1つ」まで）。notify は実行のたびに締切前の全レースを評価するため、取り消された回の処理は次の回で行われる。これを受け入れる。
5. **push の時期**：notify の実行中の回がないことを Actions の画面で確認してから push する。時間帯は D7（最終レース後〜翌朝 07:00）を候補とする。
6. **手動実行**：本書は workflow_dispatch による実行を承認しない。

## 4. 適用後の確認と戻す方法

- 確認：適用後の実行で、①実行が通常どおり始まり完了すること、②2つの実行が重なる場面では、後の実行が「待機」になり、前の実行の終了後に始まること（または取り消されること）。`[ML] モデル読み込み成功 特徴量=42` が引き続き出ること。
- 次のいずれかで戻す：workflow の構文エラーで実行されない／定期実行が1日を通して1回も完了しない／実行中の回が取り消される。
- 戻す方法：`notify_arashi.yml` を変更前（blob `a0c21870807e42aae54c93524cd807da66c0cf04`）に戻す新しい commit。force push はしない。

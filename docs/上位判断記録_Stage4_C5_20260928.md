## 3. B1 判断：案C の位置付け

1. 案C（per-race plain text の本文仕様）および独立 formatter の作成は、**ユーザーの指示により採用された実装方針**である。
2. `notification/body_formatter.py` という**具体的な配置は、チャット上の提案によるもの**であり、ユーザーがその配置を明示的に指定・承認した記録はない。
3. 案C の採用にあたり、Phase0.5 ⑦・⑧・⑮ との整合を**正式に判断した記録はない**。
4. したがって、`notification/body_formatter.py` を、Phase0.5 に適合した既存設計内の実装として、**現時点では確定扱いしない**。

本判断は、案C または `notification/body_formatter.py` の良否を評価するものではなく、誤実装・設計違反と判断するものでもない。確認できているのは、案C がユーザーの指示による実装方針として採用されたこと、およびその採用を Phase0.5 との設計差分として正式に承認した上位判断が存在しないことである。

## 4. B2 判断：C5 の達否

### 4.1 判断内容

C5 の達否は**保留**とする。「達成」とも「未達」とも判定しない。

### 4.2 根拠

C5 の定義「本番通知に必要なメール本文が生成される」に対し、確認できている事実は次のとおりである。

| 事実 | 内容 |
|---|---|
| 実装 | `notification/body_formatter.py` が存在する（commit `0c726e9`） |
| 単体テスト | `tests/unit/test_per_race_notification.py` が存在する |
| 実データでの生成確認 | 記録はない（継続基準書 §11 の実データ検証は 2026-09-13 であり、本文 formatter の実装より前である） |
| 本番評価入口 | `pipelines/production_evaluation_entry.py` では本文は生成されない（Renderer なしの構成のため） |
| 実データで本文を生成する既存構成 | `build_production_bundle()` は実際の MailNotifier と結びついており、実送信を伴わずに実データで本文を生成する既存の実行入口はない |

- 実装は存在するが、本番の経路で実データにより本文が生成されることは確認されていない。よって「達成」とは判定しない。
- 「未達」と判定するには、C5 に照らして不足している事項が確定している必要があるが、その判断は行われていない（B1・B3・B4 が未判断・未解決である）。よって「未達」とも判定しない。

## 3. B1 判断：Stage 3 差分の扱い

### 3.1 判断内容

1. 現在確認されている Stage 3 の差分について、**直ちに Rebuild の実装修正へは進まない。**
2. 継続基準書 §12 の「Stage 3内で修正するか別Stageへ回すか」という二択は、**現時点では適用しない。**
3. `race_type` の差分の原因は、**未確定として残す。**
4. `20260704_21_06` の `upset_score` 6.274 対 0.0 の原因は、**未確定として残す。**
5. `upset_score` の設計上の入力差について、現時点の資料だけから Rebuild の実装バグとは断定しない。
6. `buy_decision` および `skip` の差分について、今回の Shadow 比較経路だけを根拠に Rebuild の実装差分とは扱わない。
7. 本判断によって、新しい修正対象、移行先の Stage、Step5 への差し戻し、新しい G2 成立手段は定義しない。

### 3.2 本判断の意味

本判断は、**差分を「問題なし」と認定するものではない。** 現時点の証拠では、Rebuild の実装修正も Stage の移行も正式に決定できないことを記録するものである。

### 3.3 根拠

- Step6-0 §⑤ は、差分が出た場合「コードで補正しない（Feature Freeze維持）」「差分は原因調査対象」としている。
- 継続基準書 §8 は、Stage 3 を「測定のみ、実装しない」としている。
- §12 の二択は「原因を記録し」たうえで行う判断である。race_type と `20260704_21_06` は原因が未記録であり、upset_score と buy_decision は経路までの記録にとどまる。差分は Freeze 起因・非Freeze 起因のいずれにも区分されていない。
- §12 には、Stage 3 内で修正する対象も、回す先の Stage も記載されていない。Step6-0 の「Step5へ差し戻し」は Step 体系の記載であり、Stage 体系との対応は記録されていない。
- No-Go時の扱い（Step6-0 §⑤・Step5-0 ⑥）には、正式設計に由来する入力差を扱う区分の記載がない。
- Legacy、K1、A1（config の SHA）、Feature Freeze 対象、過去の正式記録は、継続基準書 §7 により原則変更禁止とされている。また、Shadow comparator / runner は、引き継ぎメモ §9-4 により変更しないこととされている。

## 2. M8：「100連続」

### 2.1 FACT

| # | 事実 | 箇所 |
|---|---|---|
| M8-F1 | 1レースは、`TARGET_RACES` の1要素（`YYYYMMDD_venue_race`）であり、eval_id 1件に対応する | `shadow_entrypoint.py` `parse_target_races`・`run_shadow_multiple` |
| M8-F2 | 比較可能なレースごとに、`aggregator.record()` を通じて `ConsecutiveMatchCounter.record()` が1回呼ばれる | `aggregator.py` `record`、`staged_comparator.py` `ConsecutiveMatchCounter.record` |
| M8-F3 | evaluation 段の diff は、streak の判定から除外される（`STREAK_EXCLUDED_STAGES = {"evaluation"}`）。diff 自体は記録に残る | `aggregator.py` `STREAK_EXCLUDED_STAGES`・`_is_streak_excluded`・`to_staged_result` |
| M8-F4 | evaluation 段以外に diff がなければ、`all_matched` が真となる。diff の内容は解析せず、有無のみで判定する | `aggregator.py` `to_staged_result`、`staged_comparator.py` `StagedResult.all_matched` |
| M8-F5 | `all_matched` が真なら `current_streak += 1` とし、`max_streak` を更新する | `staged_comparator.py` `ConsecutiveMatchCounter.record` |
| M8-F6 | `all_matched` が偽なら `current_streak = 0` とする | 同上 |
| M8-F7 | `max_streak` は `current_streak` とは別に保持される | 同上 |
| M8-F8 | `required` は環境変数 `SHADOW_REQUIRED_MATCHES` から読まれ、未設定時は 100 である | `shadow_entrypoint.py` main 部 |
| M8-F9 | `.github/workflows/shadow_run.yml` は `SHADOW_REQUIRED_MATCHES` を設定していないため、Workflow 経由の実行では 100 となる | `shadow_run.yml` |
| M8-F10 | 実行の途中で `current_streak` が `required` に達しても、ループは止まらず、指定された全レースを処理する。`satisfied` は `current_streak >= required` で真になるのみである | `staged_comparator.py` `satisfied`、`shadow_entrypoint.py` `run_shadow_multiple` |
| M8-F11 | Go/No-Go には、実行終了時点の `current_streak` が `shadow_consecutive_matches` として渡され、`required` が `shadow_required_matches` として渡される。go_no_go の判定は `shadow_consecutive_matches >= shadow_required_matches` である | `shadow_entrypoint.py` `run_shadow_multiple`、`go_no_go.py` |
| M8-F12 | `max_streak` はレポートに出力されるが、Go/No-Go の判定には使われない | 同上 |
| M8-F13 | `TARGET_RACES` は入力順に処理され、並べ替えは行われない。複数の日付を含めることができ、streak は日付で区切られない（sent は日付ごとに1回読み込まれる） | `shadow_entrypoint.py` `parse_target_races`・`run_shadow_multiple` |
| M8-F14 | ShadowAggregator は実行ごとに新しく生成され、streak は1回の実行内で完結する。実行をまたいだ streak の永続化はない | `aggregator.py` `ShadowAggregator`、`shadow_entrypoint.py` `run_shadow_multiple` |
| M8-F15 | コード上、「D-5（GitHub Releasesでのstreak永続化）は本Stepの対象外」と記載されている | `aggregator.py` `ShadowAggregator` docstring、`shadow_entrypoint.py` `run_shadow_multiple` docstring |
| M8-F16 | 1回の実行で処理するレースの数は `TARGET_RACES` の件数で決まり、100件である必要はない | `shadow_entrypoint.py` `run_shadow_multiple` |

### 2.2 docstring 上の「連続」の記載

| # | 事実 |
|---|---|
| M8-F17 | `staged_comparator.py` の `ConsecutiveMatchCounter` の docstring は、「『連続』の定義: Shadow対象100レース連続で全段一致。途中で1件でも差分が出たら0から数え直し（100/105ではなく100連続）。」とし、出典として「Step6-1レビュー(d)」を挙げている |
| M8-F18 | 「Step6-1レビュー(d)」の原文は、今回の調査範囲（リポジトリ・プロジェクトファイル）では確認できていない |
| M8-F19 | Step6-0 §⑧(d) は、「100連続」の定義を運用開始前に確定する事項としており、正式記録上は未確定である |

本書は、M8-F17 の docstring を正式仕様として扱わない。

## 3. M9：skip

### 3.1 FACT

| # | 事実 | 箇所 |
|---|---|---|
| M9-F1 | skip の発生条件は次の2つのみである。①sent に Legacy の値がない（`build_legacy_values` が None）。②`run_and_compare` が `"_evaluate_bets returned an empty list"` で始まる ValueError を送出した。それ以外の ValueError は送出され、処理が停止する | `shadow_entrypoint.py` `run_shadow_multiple` |
| M9-F2 | `skip_race()` は、eval_id を記録し、skipped の件数を1増やす | `aggregator.py` `skip_race` |
| M9-F3 | `skip_race()` は `ConsecutiveMatchCounter.record()` を呼ばない | 同上 |
| M9-F4 | skip によって `current_streak` は変化しない（加算もリセットもしない） | 同上 |
| M9-F5 | skip されたレースは `broken_at` に入らない（`broken_at` への追加は `ConsecutiveMatchCounter.record()` の中のみ） | `aggregator.py` `skip_race`、`staged_comparator.py` `ConsecutiveMatchCounter.record` |
| M9-F6 | skip の後の通常レースは、同じ counter で処理が継続される | `shadow_entrypoint.py` `run_shadow_multiple` |
| M9-F7 | 集約では `total_races = total_seen + skipped` である | `aggregator.py` `aggregate` |
| M9-F8 | skip されたレースは、matched にも diff にも数えられない | `aggregator.py` `skip_race`・`record` |

## 4. M10：broken

### 4.1 FACT

| # | 事実 | 箇所 |
|---|---|---|
| M10-F1 | `broken_at` は `list[str]` である（`ConsecutiveMatchCounter.broken_at`。集約ではそのコピーが `ShadowAggregate.broken_at` となる） | `staged_comparator.py`、`aggregator.py` `aggregate` |
| M10-F2 | `ConsecutiveMatchCounter.record()` の不一致側（`all_matched` が偽）で、そのレースの eval_id が append される | `staged_comparator.py` `ConsecutiveMatchCounter.record` |
| M10-F3 | evaluation 段だけの diff のレースは、broken にならない | `aggregator.py` `to_staged_result` |
| M10-F4 | evaluation 段以外に diff があれば、broken になる。diff の内容（どのフィールドか）は問わない | 同上 |
| M10-F5 | broken のとき、`current_streak` は 0 になる | `staged_comparator.py` `ConsecutiveMatchCounter.record` |
| M10-F6 | broken のとき、`max_streak` は維持される | 同上 |
| M10-F7 | `broken_at` には、不一致だった各レースの eval_id が追加される。不一致が連続すれば、複数の eval_id が記録される | 同上 |
| M10-F8 | skip されたレースは `broken_at` に入らない | `aggregator.py` `skip_race` |
| M10-F9 | Go/No-Go には、実行終了時点の `current_streak` が使われる。実行の途中で `required` に達しても、その後に broken があれば、判定時点の値は `required` を下回る | `shadow_entrypoint.py` `run_shadow_multiple`、`go_no_go.py` |

## 対象

`odds_fetch.py` の3連単オッズ解析（`_parse_v3`）。
Legacy（`notify_arashi.py`）と Rebuild（`rebuild/actions/shadow_entrypoint.py`、およびそれを再利用する `rebuild/actions/production_entrypoint.py`）が同一ファイルを共有している。

## 確認した事実

### 1. 確認に使ったデータ

- 2026-10-09 戸田（jcd=02）1R の3連単オッズページ（締切時オッズ）。ユーザーがブラウザで1回表示して保存した HTML と画面写真。画面写真の数値と HTML の数値は一致した。
- この HTML はリポジトリに追加していない。
- 解析コードは origin/main（746952e）の `odds_fetch.py`（最終変更 2026-04-18、`92574f0`）。

### 2. ページの構造

- オッズ表は1つ。1着艇番は見出し（thead）の6列にある。
- 1行に1着艇ごとのオッズが6つ並ぶ。2着艇番は rowspan=4 のセル、3着艇番はその次のセルにある。

### 3. 解析結果

| 手法 | 取得件数 | 正しい組番との一致 |
|---|---|---|
| A（rowspan） | 0 | — |
| B（出現順を辞書順に割り当て） | 120 | 2/120 |
| C（文字列パターン） | 0 | — |
| 採用結果（件数最大＝B、`odds_fetch.py` 116行） | 120 | 2/120 |

手法Bは、1行に横並びの6つの値を、辞書順の連続6組番に割り当てている。120組すべてが、この規則どおりに取り違えられていることを確認した。

### 4. 取り違えた値が入るコード経路（コードで確認）

- `notify_arashi._evaluate_bets`
  - 1着艇別の平均オッズ → 市場順位（1914–1921行）
  - 市場由来確率の計算と混合（2152–2170行、2442行）
  - 1号艇1着かつ記録オッズ15倍以上の確率補正（2461行）
  - EV、80倍上限、EV閾値（2505–2514行）
  - 候補順位・bet_score・購入額（2586–2665行）
  - BuyScore への市場乖離（2699–2721行）
- `x_buyscore.calc_buyscore`：EV・オッズ・オッズ帯・市場乖離（161–199行）
- 記録・表示
  - `notify_arashi.build_message` のオッズ表示（2962・3008行）
  - sent ファイル、hit_record の `pred_odds` / `pred_ev` / `pred_prob` / `confidence`
  - `buyscore_log.jsonl`
- Rebuild：`shadow_entrypoint.py` が `odds_fetch.fetch_odds` を呼び（173・201行）、Legacy の `_evaluate_bets` に渡す。`rebuild/adapters/providers.py` の `DefaultOddsProvider` は、テスト以外から呼ばれていない。

### 5. 影響しないことを確認したもの（コードで確認）

- 危険度、荒れスコア、上位進出指数、注目選手、特徴量（計算経路にオッズがない）
- 結果の組番、払戻、的中かどうか（公式の結果から取得）
- 転がし（`x_korogashi.py` はオッズを空のまま渡す。478・510行）
- AIランキングの買い目（オッズを使わない）
- 評価記録 `evaluations/*.jsonl`（オッズの項目がない）

### 6. 既存 golden との関係

既存の golden（危険度・荒れスコア・順位・特徴量・エンジン・BuyScore 70件・hit_record 100件）は、どれもオッズ解析を通らない。BuyScore golden は記録済みのオッズを入力として固定している。そのため、既存 golden が変わらないことは、解析の正確性の証明にはならない。

### 7. BuyScore 設定

- git 上の `buyscore_config.json` の SHA-256 は `da6a4eda…`。この値は、`docs/freeze_baseline.md` に記録された凍結時の値、`freeze-v1-baseline` タグ時点の値、`1357d99`（2026-07-02、新規作成）の初期版のいずれとも一致する。
- 2026-10-09 時点で、Release（data-store）に `buyscore_config.json` と `.bak` は存在しない（公開の取得 URL が 404。同じ Release の他の資産は取得できた）。`x_buyscore.py`（47–52行）は、Release から取得できない場合、手元のファイルを使う。
- 2026-07-02〜07-13 は、チューナーが保存ありで動いていた（07-13 の `d258757` から `--dry-run`）。その期間に Release 上の設定が書き換えられたかどうかは、記録がなく分からない。

## 推定・未確定事項（事実ではない）

- **発生期間：** 未確定。ページ構造を確認できたのは 2026-10-09 の1ページだけ。2026-05-13〜07-04 の hit_record は取り違えと矛盾しない（的中6件の記録オッズと払戻の比が 0.27〜0.98、取り違えの規則で結果と一致した例が1件）。ただし、全期間・全レースで発生していたとは断定できない。
- **損益への影響：** 定量化できない。過去の記録には、正しい120通りのオッズも取得時刻も残っていないため、正しいオッズでの購入判定を再計算できない。
- **影響の大きさ：** 2461行の補正と、市場由来確率の混合がどれだけ結果を変えたかは未確定。
- **BuyScore 設定への影響：** 未確定。現在の運用設定は、Release に設定がないことから git 上の初期値と推定されるが、実行ログでは確認していない。

## 暫定対応

# インシデント記録: notify の既定日付が UTC になっている（JST 8:30・8:45 の実行で前日扱い）

記録日: 2026-10-09 ／ 検出日: 2026-10-08（現行コード整合性レビュー）
関連: 設計書 Phase0.5 v1.1.8 ⑳20.3（稼働継続に必須の障害修正）

## 事実

| # | 事実 | 出典 |
|---|---|---|
| F1 | `_run_main()` は `race_date` が指定されないとき `date.today()` を使う。GitHub Actions のランナーは UTC で動く | `notify_arashi.py` `_run_main`（基準 commit `a3c3494`） |
| F2 | `notify_arashi.yml` の cron には UTC 23:00〜23:45（JST 8:00〜8:45）の実行がある。コード側の時間帯フィルタは JST 8:20〜22:45 のため、JST 8:30 と 8:45 の実行が通過する | `.github/workflows/notify_arashi.yml`、`notify_arashi.py` `run` |
| F3 | この2回の実行では `race_date` が前日になる。同じ関数内の時間帯判定・締切判定・出走表取得は JST を使っている | 同上 |

## 修正

`_run_main()` の既定日付を `datetime.now(JST)` から求める。

## 影響

JST 8:30・8:45 の実行で当日分が処理されるようになる。評価式・閾値・BuyScore 計算は変わらない。

## ゴールデンデータ

評価エンジン・BuyScore 計算のコードは変更しないため、スナップショットは変わらない。

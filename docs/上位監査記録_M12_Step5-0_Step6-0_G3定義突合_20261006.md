## 7. 仕様系譜の分岐点

1. **Phase0.5 → Step5実装計画書**
   - Phase0.5 では BuyDecision が1つのモデルであった。
   - Step5実装計画書では、BuyAssessment と BuyDecision へ責務が分けて記述されている。
   - 分割の根拠とされる Step4-6 の原資料は未確認である。
2. **Step5-0 → Step6-0**
   - G3 の対象の名称が、BuyDecision から BuyAssessment へ変化した。
   - 4項目の内容は対応している。
   - Step5-0 の cost・n_bets の未確定は、Step6-0 に引き継がれていない。解消したという明示の記録もない。
3. **§9**
   - G3 が G3-A/B/C へ再構成された。
   - G3-A は、Step6-0 の G3 と内容上対応する。
   - G3-B は、cost・n_bets・purchased である。
   - G3-C は、新規の内訳項目である。
4. **§8.6**
   - buy_decision が、正式条件外の追加観測項目として位置付けられた。
   - G3-B・G3-C を正式G3へ昇格した記録はない。

## 8. 既存監査記録との差異

G2/G3状態整理 §4 は、Step5-0 の G3 と Step6-0 の G3 について、「資料間の明確な矛盾」（X1）として整理している。

今回の原資料の突合では、**この「明確な矛盾」という表現は強すぎる。** 理由は次のとおりである。

- Step5-0 の4項目と、Step6-0 の「buyscore4項目」は、内容上対応する。
- Step5実装計画書に、「BuyAssessment 4項目」の記載がある。
- BuyDecision から BuyAssessment への名称・責務の変化は、Step5実装計画書の記載により説明できる。
- 同じ層・同じ意味の正式資料同士で、直接矛盾する記載ではない。

したがって本書では、**既存監査記録 X1 の「明確な矛盾」という分類は、今回の原資料の追加確認により過大評価と判明した**と記録する。

ただし、「Step5-0 の G3 と Step6-0 の G3 が同一の正式条件である」とも決定しない。G2/G3記録 §3.3 の「同一の正式G3とは確定しない」という扱いは維持する。

## 10. 結論

1. Step5-0 の G3 と Step6-0 の G3 は、4項目の内容上の対応は確認できるが、同一の正式条件とは決定しない。
2. BuyAssessment と BuyDecision の責務の分離は、Step5実装計画書で確認できる。
3. ただし、その分離の一次根拠とされる Step4-6 の資料は未確認である。
4. §9 の G3-A/B/C は、後から再構成された作業定義（[B]）であり、G3-B・G3-C が Step6-0 の正式G3の正式な後継であることは確認できない。
5. G3-B・G3-C を正式G3へ昇格する根拠は、現時点でない。
6. G2/G3状態整理の X1「明確な矛盾」は、今回の原資料の突合により、強すぎる分類と判明した。
7. しかし、既存記録を今回の作業で直接変更しない。
8. M13・M14 では、今回確認した原資料上の対応関係を、前提資料として利用できる。
9. 本書では、G3 の正式定義、Stage 3 の完了、G2・G3 の達成、Stage 6 の開始を判断しない。

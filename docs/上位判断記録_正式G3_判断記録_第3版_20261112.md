## 5. 診断段階 (a)

- 目的：入力の受け渡し・変換・配線・計算式の不具合を切り分ける。
- 方法：`_evaluate_bets` を1回だけ呼び、apply_buyscore 呼び出し時点の引数（候補・context）を写し取り、同じ入力を Rebuild の BuyScore 処理に渡して比べる。
- 上流の評価の独立した再現性は証明しない。
- 結果は正式G3 の100連続の証拠に使わない。

## 6. 正式G3 候補段階 (b-2)：ハイブリッド方式

- 評価：Rebuild の RaceEvaluation と UpsetResult（upset_score・target_lanes・match_index・race_type）を使う。ML 加点と target 入れ替えは Rebuild が行う（実装が必要）。
- 予想：Rebuild の UpsetResult の upset_score・target_lanes（そこから作る patterns）を PredictionContext に渡し、Legacy の `_evaluate_bets` を1回だけ呼ぶ（§④ PredictionProvider 経由、Step5-0(a)）。
- BuyAssessment：写し取った候補と context（uncertainty・disagreement・composite・market_gap 等）を、専用の入力型（方式3。入力型と assess の引数の設計は、段階1の変更案で本人が承認する）で assess に渡し、assess が4項目を計算する。
- 同一性の条件：RaceEvaluation と PredictionContext の upset_score・target_lanes は**同一でなければならない**。食い違いは入力不備とする。
- 独立の範囲
  - **完全な独立再現ではない**。検証するのは Rebuild の評価経路と BuyScore 経路である。
  - Prediction の生成は Legacy 依存であり、独立していない。
  - オッズの取得も独立していない（1回の取得を両方で共有する）。
  - G3 の成功を完全独立再現の証明と表現しない。

## 9. match_index_approx

- (b-2) では True を、Legacy と同じ挙動を再現する候補とする。
- 比較対象は BuyAssessment の4項目。approx の印・match_index の両方の値・40未満か否かは診断メタデータとして記録する。
- True は「AI一致指数不足」の見送りを無効にするため、**本番仕様としての採用には別途の明示的な承認を要する**。

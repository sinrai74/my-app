## 3. 採用の根拠（直接検証した事項・確認事実）

1. **結合キーの修正**：結果ラベルを、日付・場・レース・艇番が一致する行だけに結合する（`parsers.attach_k_results(..., date_col=...)`、`retrain.py`）。単体テスト10件が成功（`test_retrain_label_date_key_20261012.py`、`docs/上位監査記録_J1_D3_修正検証_20261012.md` §3）。
2. **行数の整合**：学習ログ「ラベル検証: 28日 / 4068レース / 24408行 / 結果なし 50レース」「結果付与 24408 / 24408 件」。24,408 = 4,068 × 6。修正前の学習データは 193,989 行。
3. **ラベルの一意性**：`check_label_integrity` は、1着ラベルが2艇以上のレースがあると停止する。run `38236386660` は停止せずに完了した。
4. **読み込みの確認**：scikit-learn 1.5.2 の環境で、本番の `notify_arashi._load_ml_model()` が True を返し、特徴量は42個。
5. **入力に対する挙動（合成データ）**：6艇の勝率の合計は 1.000。1号艇が強い入力で1号艇 0.774、4号艇が強い入力で4号艇 0.335。置き換え前のモデルは、同じ入力で1号艇 0.400（全艇が同程度の入力で 0.415）だった。

合成データでの確認は、上記4・5（読み込み・特徴量の数・確率の合計・入力に対する挙動）に限る。合成データの結果を、未知のデータでの性能、的中率、回収率の証拠として扱わない。

- 1着 AUC（修正前 0.7909、修正後 0.8988）は学習データ上の値であり、採用の根拠にしない。
- **未知のデータでの性能は未評価である。** 的中率・回収率への影響も未評価である。

## 5. Golden（⑳20.3）

- ML の出力（`_predict_win_prob` の値）は、既存の golden（`rebuild/tests/regression/` の golden・golden4・golden_buyscore）の対象外である。そのため、⑳20.3 の golden の比較では、本変更の影響を確認できない。
- 既存の golden の保存値は変更しない。J1・D3 の修正前後で golden のスナップショットに差分がなかったこと（上位監査記録_J1_D3 §5 G3）を、golden 全体の合格や、golden4 の既存の差の承認に広げない。
- ⑳20.3 の条件は緩和しない。

## 6. 判断

1. §2 のモデルを、本番の `model_all.pkl` として採用する。変更するファイルは `model_all.pkl` だけとする。
2. 置き換えの前に、本書と B1 の incident（`docs/incidents/2026-10-12_ml-model-load-sklearn-version.md`）を保存する（⑳20.3）。
3. 置き換えは、Web UI（`app.py`）への影響の確認（§7）が終わった後に、別の段階として行う。
4. 週次の自動再学習は、無効のまま維持する（D3-4。再開は別途判断）。有効にすると、定期実行で作られたモデルが本モデルを上書きするため。

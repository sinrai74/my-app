## 2. 判断の内容

### 2.1 M7-3（Runner Image）【本人承認。07h §2.1・§2.2】
- 正式G2 の評価ジョブの Runner Image は、ジョブログの「Set up job → Runner Image」グループの Image の値で識別し、`ubuntu-24.04` に固定する。
- Version は、実行ごとの観測値としてジョブログから記録する。基準との一致は求めない。Version の値が違うことだけでは不合格にしない。
- ジョブログに Version の行が無い、または一意に読めない場合は、そのジョブログの検証を不合格にする。
- Image を一意に取り出せない、または Image が基準と違う場合は、その実行を正式カウントに入れない。
- Python の版は M7-3 の対象ではない（評価側の baseline の項目。07h §2.3）。
- 残余リスク：Version の更新で、lock の外にあるシステムのソフトウェアが変わり、評価の結果に影響しうる。これは、Python の版・lock・installed・code の照合では検出できない範囲として受け入れる。

### 2.2 baseline の登録方式（案A）【本人採用。07h §2.8】
- 登録の承認記録は `g2_baseline/registered/approvals.json` に置く。
- 評価側（evaluate）と集約側（aggregate）の基準を、それぞれちょうど1件登録する。登録する基準のファイルは `g2_baseline/registered/evaluate/` と `g2_baseline/registered/aggregate/` に置く。
- 承認記録の各行は、種類・パス・SHA-256・承認日を必須とする。
- 登録する基準のファイルが置かれているだけでは、登録とみなさない。
- 承認記録、登録したファイルの実体、集約に渡された基準の、パスと内容の SHA-256 がすべて一致した場合だけ、登録を確認できたとする。
- 登録を確認できない場合は、正式な合格・正式カウントへの加算を認めない（07h §2.9）。
- 本項は登録の方式を決めるもので、どの基準を登録するかは決めない。実際の登録（基準の配置と承認記録の commit）には、本人の許可が別に要る。

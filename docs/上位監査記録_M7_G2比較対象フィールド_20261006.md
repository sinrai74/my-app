## 2. FACT

### 2.1 比較の仕組み

| # | 事実 | 箇所 |
|---|---|---|
| F1 | `compare(eval_id, legacy, rebuild, path)` は、legacy・rebuild を `to_comparable` で dict 化し、JSON で正規化した後に再帰比較する | `comparator.py` `compare` |
| F2 | dict 同士の比較では、Legacy 側のキーを基準に回る（`for key in sorted(set(le))`）。Rebuild 側にのみ存在するキーは比較されない | `comparator.py` `compare` 内 `rec` |
| F3 | list 同士の比較では、長さが異なれば `<path>.__len__` の差分として検出し、対応する範囲（zip の範囲）を要素ごとに比較する。それ以外の値は `!=` で比較する | 同上 |

### 2.2 evaluation 段

| # | 事実 | 箇所 |
|---|---|---|
| F4 | Rebuild 側の evaluation は、`evaluation_pipeline.evaluate_race(..., persist=False)` が返す RaceEvaluation であり、`to_comparable` により `RaceEvaluationSerializer.to_dict` で dict 化される | `runner.py` `run_and_compare`、`comparator.py` `_SERIALIZERS` |
| F5 | `RaceEvaluationSerializer.to_dict` の出力には、schema_version、eval_id、race_date、venue_num、venue_name、race_number、is_night、engine_name、engine_version、feature_schema_version、model_version、evaluated_at、danger_score、danger_breakdown、upset_score、upset_reasons、rank_index、featured_boats、win_probs、race_type、match_index、features、hot_motor_score、awakening_score、local_advantage 等が含まれる | `evaluation_serializer.py` `RaceEvaluationSerializer.to_dict` |
| F6 | Legacy 側の evaluation は、sent の1行の `LegacySentRecord.evaluation_view()` である | `legacy_values_builder.py` `build_legacy_values`、`legacy_source.py` |
| F7 | 現在の `evaluation_view()` は、sent の生 JSON に該当キーがある場合のみ、次の最大3キーを返す：`upset_score`（sent の `upset_score`）、`race_type`（sent の `race_type`）、`danger_score`（sent の `danger_score_v3` を名称変換） | `legacy_source.py` `evaluation_view` |
| F8 | `evaluation_view()` が空の dict であれば、`build_legacy_values` は `evaluation` のキーを作らず、evaluation 段の比較は行われない | `legacy_values_builder.py` `build_legacy_values`、`runner.py` |
| F9 | したがって、現行の evaluation 段の比較で実際に対象となるのは、Legacy 側の evaluation_view にあるキー（最大3キー）だけである。Rebuild の RaceEvaluation のその他のフィールド（F5）は比較されない。diff の `field_path` は `$.evaluation.<key>` である | F2・F4〜F8 |
| F10 | evaluation 段の diff は、streak の判定から除外される（`STREAK_EXCLUDED_STAGES = {"evaluation"}`）。diff 自体は記録に残る | `aggregator.py` |

### 2.3 ほかの段

| # | 事実 | 箇所 |
|---|---|---|
| F11 | race 段では、Legacy 側の `race_view()` の4キー（`venue_num`、`race_number`（sent の `race`）、`is_night`（sent に `night` があれば bool、なければ None）、`venue_name`（sent の `venue`））が、Rebuild 側の `evaluation_pipeline._race_source.resolve_race(...)` の Race と比較される。diff の `field_path` は `$.race.<key>` である | `legacy_source.py` `race_view`、`runner.py` `run_and_compare` |
| F12 | buy_decision 段は、evaluation 段とは別の段として比較される（Legacy 側は `purchase_view()`、`field_path` は `$.buy_decision.<key>`） | `legacy_source.py` `purchase_view`、`runner.py` |
| F13 | `build_legacy_values` が生成するのは race・evaluation・buy_decision の3つのキーだけである。`runner.py` の docstring が挙げるその他のキー（feature_set、prediction、buy_assessment、render_results、notification_requests）は生成されず、`legacy_source.py` に定義されている `prediction_view`・`buy_view`・`feature_view` は、複数レースの Shadow の経路では builder から呼ばれていない | `legacy_values_builder.py`、`runner.py` docstring、`legacy_source.py` |
